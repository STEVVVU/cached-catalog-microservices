- The bounded current-build cache preset is `python3 scripts/catalog-benchmark.py --k6 --focused-cache --output reports/evidence/k6-focused-cache`. It uses the frozen 500-product fixture, one gateway, 60-second TTL, 100 offered operations/s for 20 seconds, the existing 50/40/10 mix and 64-VU cap, and five repeats with reversed cache-arm order alternating. Each of its 15 arms gets a fresh database and gateway and a one-operation Go exact protobuf oracle. It retains and hashes native summaries, compressed streams, oracle receipts, logs and outcome/resource samples. The post-run audit reads every gzip stream through its CRC, reconciles native and custom counts, and recomputes p50/p95/p99 from raw trends. A result passes only when every cell ran all 2,000 operations with zero failures, timeouts, drops, interruptions, or missing native successful-RPC duration samples; otherwise it stays inconclusive. This moderate fixed-load comparison is not a capacity claim. The workflow exposes it with `focused_cache=true`, runs the lifecycle verifier and race tests, and uses a 20-minute job ceiling; smoke remains the default.
